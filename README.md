# lab-web-4

Student Management System — веб-приложение (SPA) на Angular для управления записями студентов через REST API. Проект реализует CRUD-функции, поиск и пагинацию без перезагрузки страниц. Включает авторизацию на базе JWT, глобальное состояние (Signals/NgRx) и реактивную логику через RxJS. Полностью контейнеризировано с помощью Docker, Docker Compose и Nginx.

## 📝 Лабораторная работа №4. Frontend на JavaScript-фреймворке

### Цель
В рамках лабораторной работы необходимо перенести frontend системы управления студентами из лабораторной работы №1 на современный JavaScript-фреймворк, сохранив основную функциональность и добавив авторизацию, разграничение прав доступа, управление состоянием и реактивное программирование. Приложение должно взаимодействовать с REST API, разработанным в лабораторной работе №3.

### Варианты реализации
В зависимости от варианта необходимо использовать один из следующих фреймворков:
- React;
- Vue;
- Angular;
- Svelte.

Использование библиотеки RxJS обязательно для всех вариантов.

### Работа со студентами
Необходимо сохранить функциональность лабораторной работы №1. Приложение должно поддерживать просмотр списка студентов и подробной информации об отдельном студенте, создание, редактирование и удаление записей. При работе со списком необходимо реализовать поиск, фильтрацию по всем полям, сортировку и пагинацию. Все данные должны загружаться через REST API лабораторной работы №3. Изменения должны отображаться без перезагрузки страницы.

### Авторизация и JWT
Необходимо реализовать регистрацию, авторизацию, выход из системы и просмотр информации о текущем пользователе.

Обязательные страницы:
- /login — авторизация;
- /register — регистрация;
- /profile — профиль пользователя.

Для авторизации необходимо использовать JWT с поддержкой access- и refresh-токенов.

### Компонентная архитектура
Приложение должно быть построено с использованием компонентов выбранного фреймворка. Необходимо использовать локальное состояние компонентов, передачу данных через props / inputs, hooks или lifecycle-механизмы, условный рендеринг и клиентскую маршрутизацию. Конкретная структура компонентов и организация проекта определяются разработчиком.

### Управление состоянием
Необходимо использовать глобальное состояние приложения. Допустимые варианты:
- React — Context API / Redux Toolkit / Zustand.
- Vue — Pinia.
- Angular — Signals / NgRx.
- Svelte — Stores / Runes.

### Реактивное программирование
В приложении необходимо реализовать реактивную обработку пользовательских событий и асинхронных данных с использованием RxJS. Для реализации необходимо использовать Observable, mechanisms подписки и операторы RxJS, соответствующие решаемым задачам. Реактивная логика должна быть отделена от логики отображения интерфейса и организована таким образом, чтобы ее можно было повторно использовать. Простое подключение RxJS без практического применения в указанных сценариях не считается выполнением требования.

### Валидация и обработка ошибок
Необходимо реализовать клиентскую валидацию форм и обработку ошибок backend. Приложение должно корректно обрабатывать ошибки авторизации, недостаточность прав доступа, истечение срока действия токенов, ошибки валидации, отсутствие запрашиваемых данных, недоступность сервера и внутренние ошибки backend. Пользователь должен получать понятные сообщения об ошибках. При выполнении асинхронных операций должна отображаться индикация загрузки. Необходимо предусмотреть защиту от повторной отправки форм во время выполнения запросов.

### Контейнеризация и запуск
Все приложение, включая frontend лабораторной работы №4 и backend лабораторной работы №3, должно запускаться совместно в Docker с помощью Docker Compose.

- Настроить раздачу собранного frontend-приложения через Nginx или аналогичный веб-сервер.
- Создать docker-compose.yml для совместного запуска frontend и backend лабораторной работы №3.

# Контейнеризация и запуск приложения (Лабораторные работы №4)

Данный проект объединяет REST API на **Spring Boot** (Лабораторная работа №3) и фронтенд на **Angular** (Лабораторная работа №4) в единую изолированную экосистему с помощью **Docker** и **Docker Compose**.

## 🏗️ Архитектура системы

- **Frontend (Angular)**: Собирается с помощью многоэтапной сборки (Multi-stage build). На этапе запуска работает под управлением веб-сервера **Nginx**, который отдает статические файлы.
- **Backend (Spring Boot)**: Развертывается в JRE-контейнере и использует встроенную базу данных **SQLite**. Для сохранения данных между перезапусками контейнера настроен Docker Volume.
- **Reverse Proxy (Маршрутизация)**: Nginx на фронтенде настроен как прокси-сервер. Все запросы к API (начиная с пути `/api/`) автоматически перенаправляются на контейнер бэкенда через внутреннюю сеть Docker. Это решает проблему CORS и избавляет от необходимости жестко прописывать URL бэкенда в коде фронтенда.
- **CI/CD**: Настроен пайплайн в GitHub Actions для автоматической проверки сборки контейнеров при каждом пуше.

## 🚀 Инструкция по сборке и запуску

### 1. Подготовка конфигурации (Настройка параметров окружения)
Параметры конфигурации, зависящие от окружения, вынесены за пределы исходного кода в файл `.env`.

Перед первым запуском скопируйте шаблон конфигурации из файла `.env.example` в новый файл `.env`:

```bash
cp .env.example .env
```

Откройте созданный файл `.env` и при необходимости измените порты или секретные ключи. Для тестирования локально можно оставить значения по умолчанию:
- `FRONTEND_PORT=80` (Доступ к веб-интерфейсу)
- `BACKEND_PORT=8080` (Доступ к API бэкенда)
- `JWT_SECRET` (Секретный ключ для авторизации)

> ⚠️ **Важно:** Файл `.env` содержит конфиденциальные данные, поэтому он автоматически добавлен в `.gitignore` и не попадет в общий репозиторий.

### 2. Запуск приложения
Запустите сборку и старт всех сервисов одной командой. Docker Compose автоматически скачает необходимые базовые образы, скомпилирует исходный код Java и Angular, настроит сеть и запустит контейнеры:

```bash
docker compose up --build
```

После успешного завершения сборки и инициализации базы данных приложение будет доступно по следующим адресам:
- **Веб-интерфейс (Angular)**: [http://localhost](http://localhost) (или порт, указанный в `FRONTEND_PORT`)
- **REST API (Spring Boot)**: [http://localhost:8080/api](http://localhost:8080/api) (или порт, указанный в `BACKEND_PORT`)

## 🛑 Остановка и управление приложением

### Остановка контейнеров
Чтобы остановить работу приложения и освободить порты, нажмите `Ctrl + C` в терминале, где запущен процесс, либо выполните в папке проекта команду:

```bash
docker compose down
```

### Полная очистка (Сброс данных)
База данных SQLite сохраняется в изолированном томе Docker (`sqlite-data`). Если вам необходимо полностью удалить контейнеры, очистить кэш сборки и сбросить базу данных до первоначального состояния (удалить созданных пользователей и прогнанные миграции Flyway), выполните команду:

```bash
docker compose down -v
```

## ⚙️ CI/CD Автоматизация

В проекте настроен пайплайн GitHub Actions (`.github/workflows/docker-ci.yml`), который запускается автоматически при каждом `git push` или `Pull Request` в ветки `main` и `master`. 

Пайплайн выполняет следующие шаги:
1. Клонирует актуальный код репозитория на виртуальную машину.
2. Инициализирует окружение и создает временный `.env` файл на основе секретов репозитория (**GitHub Secrets**).
3. Проверяет синтаксическую корректность структуры файла `docker-compose.yml`.
4. Тестирует сборку Docker-образов фронтенда и бэкенда с использованием кэширования для подтверждения стабильности релиза.
